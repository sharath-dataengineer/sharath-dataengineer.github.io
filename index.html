Agentic AI reconciliation and validation

Production
RoleDesigned and built the reconciliation layer and the agentScale~16K mismatched units, 4 product linesKey callDeterministic 8-reason classification under the agent, so each explanation cites evidence

Problem

Two reporting systems disagreed on unit counts. Analysts spent days per cycle working out why, and nobody trusted either number.

Approach

  • Built a reconciliation layer that classifies every mismatched unit into one of 8 root-cause reasons.
  • Added an AI agent that runs the validation, explains each gap and proposes the fix.

Outcome

~16K mismatched units classified automatically into 8 reasons. A partner team adopted the agent for their own validation work.

  • LLM agents
  • Reconciliation
  • Spark SQL
  • Data validation
  • Root-cause classification

Config-driven analytics foundation

Production
RoleDesigned and built the frameworkScale~74 logical pipelines, 5–6 environments, up to 11 regional variants, 5 source systemsKey callConfig over bespoke jobs, and DQ gates that block rather than alert

Problem

Contact-center, CRM, clickstream and sales-booking data shared no common key, so the recommendation-to-revenue funnel could not be measured. Every new table meant bespoke Spark code.

Approach

  • Defined each pipeline as HOCON config on one shared Spark-on-EMR framework.
  • Built 7-day first-touch attribution across 5 source systems.
  • Added golden-check DQ gates that block publishing, not just alert.

Outcome

~74 logical pipelines as config, no bespoke Spark code per table. 50% fewer data incidents and test coverage up from ~30% to 90%+.

  • Spark
  • EMR
  • HOCON config
  • SCD2
  • DQ gates
  • Attribution

Autonomous data platform

Reference architecture
RoleArchitect; designed the monitoring coreScaleReference design with ADRs; core derived from a production systemKey callPredict failures before they happen, then explain them with an LLM

Problem

Platform teams lose on-call time to failures a system could detect, explain and often prevent: schema drift, silent quality decay and cost surprises.

Approach

  • Designed a self-operating platform: drift detection, AI-assisted root cause, per-pipeline cost attribution and an operator copilot.
  • Recorded each decision as an ADR with trade-offs.

Grounded in

A monitoring core from a production system that cut incident resolution time by 70% by removing manual log triage.

  • Schema drift
  • LLM root cause
  • FinOps
  • Copilot
  • ADRs
